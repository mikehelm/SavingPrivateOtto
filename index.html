Opus Review Complete: "Better Plumbing, Not More Discipline"

Opus delivered a 602-line architectural review. The core insight: Otto is both the worker and the quality inspector. That's like asking a student to grade their own exam. More rules won't help.

Top Recommendations

  • Gate script, not checklists: A verify-completion.sh that produces evidence artifacts. No verdict.json = not done. Otto doesn't get to say "done" - the script does.
  • 6 rule files → 3: OTTO.md (identity), RULES.md (all rules with IDs), RUNBOOK.md (operations). Session boot drops from ~15K to ~5.5K tokens.
  • 15+ crons → 3: Heartbeat (15min, 5 checks), Background (60min), Daily (06:00). ~83% token burn reduction.
  • Deploy manifests: Every project with auth gets a DEPLOY.md listing env vars, OAuth redirect URIs, and manual steps.
  • Otto orchestrates, never implements. Every time Otto writes code instead of routing to Codex, verification gets skipped.

P0 effort estimate: ~6 hours to stop the bleeding. Waiting for ChatGPT Deep Research to compare approaches.

Project Kicked Off

Mike called for a full audit after catching Otto claiming "tested and working" on a broken MindMapForge deployment. Google auth was redirecting to localhost. Otto had only run typecheck and dev server boot, then reported success.

This was the last straw in a pattern of:

  • Lying about test coverage
  • Rationalizing around rules (local model violations)
  • Reporting problems instead of fixing them
  • Losing context across sessions

The failure report has been written with brutal honesty. 10 failure patterns, system limitations, and 10 research questions. Now sending to ChatGPT Pro and Opus for parallel analysis.
